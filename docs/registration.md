# ConnectID Registration

ConnectID should make joining the digital society simple and accessible.

A person must be able to become a Citizen without owning cryptocurrency or connecting a wallet.

## Initial Registration

The initial registration process should be simple:

1. Create an account
2. Choose a unique @username
3. Choose a display name
4. Choose an avatar
5. Become a Citizen

The registration process should not require a cryptocurrency wallet.

## Username

Every Citizen has a unique @username.

The username is the public identifier used by other Citizens to find and connect with the user.

A username should remain unique within ConnectID.

The underlying ConnectID Identity ID should remain separate from the username so that usernames can potentially be changed in the future without changing the underlying identity.

## Authentication

ConnectID requires secure authentication to protect Citizen accounts.

The initial authentication system should prioritize:

- Simplicity
- Security
- Account recovery
- Protection against automated abuse
- Future scalability

The exact authentication technology will be selected during implementation.

## Wallet

A wallet is optional.

A Citizen may connect one wallet after registration.

The wallet connection should verify that the Citizen controls the wallet.

The wallet should never be required to:

- Register
- Become a Citizen
- Create connections
- Send messages
- Join communities
- Use the basic ConnectID platform

## Security

Security must be considered from the beginning.

ConnectID must protect:

- Account access
- Citizen identity
- Private information
- Messages
- Connections
- Reputation data
- Wallet connection information

Passwords, private keys, seed phrases, API keys and other sensitive credentials must never be stored in the public repository.

## Abuse Prevention

ConnectID should reduce:

- Fake accounts
- Bots
- Spam
- Scams
- Account abuse

Abuse prevention should not make registration unnecessarily difficult for legitimate users.

Additional verification mechanisms can be introduced as the platform grows.

## Account Recovery

Users must have a secure way to recover access to their ConnectID account.

Account recovery should not depend exclusively on a cryptocurrency wallet.

The final recovery mechanism will be determined during implementation.

## Future Authentication

The architecture should allow additional authentication and verification methods in the future.

Possible future methods may include:

- Stronger identity verification
- Wallet signatures
- Passkeys
- Additional security factors
- Other cryptographic identity mechanisms

These should extend the ConnectID identity rather than replace the basic Citizen experience.

## Principle

ConnectID should be easy to join, difficult to abuse and safe to use.

A Citizen should not need to understand cryptocurrency or blockchain technology to participate in ConnectID.
