# ConnectID Reputation Rules

## Purpose

ConnectID reputation represents trust earned through meaningful participation in the ConnectID ecosystem.

Reputation is not a popularity score.

It is not determined by the number of followers, the amount of money a user owns, or the number of connections they have.

Reputation should reflect contribution, reliability, constructive participation and responsible behavior.

## Core principles

### 1. Reputation must be earned

Users cannot choose their own reputation score.

Reputation is created through recorded events in the ConnectID system.

### 2. Reputation is separate from role

A user's role and reputation are different concepts.

For example:

- Creator = system role
- Citizen = identity status
- Reputation = earned trust

The Creator role does not automatically mean unlimited reputation.

### 3. Connections do not directly create reputation

Simply connecting with another Citizen does not award reputation.

This prevents users from creating large numbers of artificial connections to increase their score.

### 4. Wallet ownership does not automatically create reputation

Connecting a wallet does not automatically give reputation points.

A wallet can provide additional verification or context, but reputation remains based on behavior and contribution.

### 5. Reputation events are recorded

Every reputation change should create a reputation event.

Each event contains:

- user
- points
- event type
- reason
- optional actor
- optional reference
- timestamp

This creates an auditable reputation history.

## Positive reputation

Possible sources of positive reputation include:

- meaningful community contributions
- helpful participation
- trusted contributions
- successful community activity
- verified achievements
- constructive behavior
- other future ConnectID-defined contributions

Positive reputation should be awarded by system rules rather than arbitrary manual votes whenever possible.

## Negative reputation

Negative reputation may result from confirmed harmful behavior such as:

- scams
- abuse
- manipulation
- spam
- malicious activity
- repeated community violations

Negative reputation should require appropriate evidence or moderation.

A simple disagreement or unpopular opinion should not automatically reduce reputation.

## Anti-gaming principle

ConnectID reputation must be difficult to manipulate.

The system should avoid rewarding:

- connection farming
- fake activity
- self-interaction
- repeated low-value actions
- artificial community activity
- automated spam

Future reputation systems should include rate limits and abuse detection where necessary.

## Reputation visibility

A Citizen's reputation should be visible as part of their ConnectID identity.

However, reputation should remain subtle.

ConnectID should communicate:

> This Citizen has built a history.

It should not turn the platform into a leaderboard.

## Reputation and trust

Reputation is one signal of trust.

It is not absolute proof that a Citizen is trustworthy.

Users should be able to consider:

- identity history
- reputation
- community participation
- connections
- optional wallet verification
- future verification systems

## Future development

The reputation system may later support:

- reputation levels
- reputation categories
- community-specific reputation
- verified contributions
- badges
- achievements
- moderation events
- reputation decay
- reputation recovery
- advanced anti-abuse systems

Any future expansion should preserve the core principle:

**Reputation is earned through meaningful participation.**
